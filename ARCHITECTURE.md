# 🏛 Архитектура проекта Maxvent Tools

Руководство для разработчиков и AI-ассистентов по структуре кодовой базы, потокам данных и правилам расширения функционала.

---

## 1. Обзор стека и концепция

- **Frontend**: Vanilla JavaScript (ES6+), HTML5, Tailwind CSS (через CDN).
- **Backend / База данных**: Supabase (PostgreSQL + REST API).
- **Offline / PWA**: Service Worker (`sw.js`) с сетевой стратегией Cache-First/Network-First и Web App Manifest (`manifest.json`).
- **Хостинг / Деплой**: GitHub Pages (статический деплой прямо из ветки `main`).
- **Сборка**: Безбандлерная (No-build step), нативные скрипты загружаются напрямую в браузере.

---

## 2. Структура файлов и модулей

Вся логика разделена по ответственности в каталоге `js/`:

```
Maxvent-Tools/
├── index.html            # Основная разметка (SPA на экранах/модалках)
├── manifest.json         # PWA манифест для Android, iOS и Desktop
├── sw.js                 # Service Worker (кэширование и оффлайн)
├── app.js                # Точка входа / обратная совместимость
├── ARCHITECTURE.md       # Этот документ (архитектура и гайдлайн)
├── README.md             # Общее описание проекта
│
└── js/
    ├── config.js         # Конфигурация Supabase, константы, appState, session, showToast
    ├── auth.js           # Авторизация по PIN-коду, переключение Dev-режима, сессии
    ├── projects.js       # CRUD проектов/объектов, фальцевые припуски, карточки
    ├── items.js          # Спецификация изделий, форма ввода, групповое редактирование
    ├── flange.js         # 1D калькулятор шинорейки, алгоритм раскроя пачек, обрезки
    ├── nesting.js        # 2D раскрой листа для воздуховодов, канвас, экспорт в PDF
    ├── finance.js        # Учет оплат объектов, финансовые сводки и отчеты
    ├── dev.js            # Панель разработчика, конструктор изделий, кастомные параметры
    ├── workers.js        # Выработка, умное деление долей (правило Чингиса), личный кабинет
    └── main.js           # Старт приложения (DOMContentLoaded)
```

## 3. Описание модулей

### `js/config.js`
- **Ответственность**: Инициализация клиента Supabase, константы размеров (`POPULAR_RECT`, `POPULAR_DIAM`), список параметров (`ALL_PARAM_DEFS`), справочник фасонины по умолчанию (`DEFAULT_FITTINGS`).
- **Глобальные переменные**:
  - `appState`: хранит списки металлов, толщин, групп, проектов, всех изделий (`allItems`), активных изделий проекта (`activeProjectItems`), пользователей, справочник фасонины (`fittings`).
  - `session`: состояние текущего пользователя, режим dev (`devMode`), активные вкладки, выбранные чекбоксы (`selectedSpecIds`), раскрытые аккордеоны.
- **Базовые функции**: `showToast()`, `isDev()`, `isChingisOrDev(userName)`, `loadInitialData()`, `saveGlobalSettings()`.

### `js/auth.js`
- **Ответственность**: Вход по коду доступа (PIN), сохранение сессии в `localStorage` (`mv_online_session`), проверка авторизации, выход, тумблер режима разработчика (`toggleDevMode()`), обновление шапки профиля.

### `js/projects.js`
- **Ответственность**: Отрисовка списка объектов на главном экране, создание и редактирование проектов (модалка `projectModal`), припуски фальцев (`modalProjSeamBig`, `modalProjSeamSmall`, `modalProjSeamRound`), переход внутрь объекта (`openInsideProject()`).

### `js/items.js`
- **Ответственность**:
  - Динамическая форма параметров для воздуховодов и фасонных изделий (`renderDynamicInputs()`).
  - Автоматическое суммирование одинаковых позиций при добавлении в спецификацию.
  - Рендеринг таблицы/аккордеонов спецификации изделий (`renderSpecification()`, `renderSpecItemRow()`).
  - Переключение статуса изделия между **`Не готово`** (`queue`) и **`Готово`** (`done`).
  - Групповые действия: выбор всех позиций (`toggleSelectAllSpecItems`), массовая смена статуса (`batchSetStatus`), модалка массового редактирования (`bulkEditModal`).

### `js/flange.js`
- **Ответственность**:
  - Оптимизированный алгоритм 1D раскроя шинорейки (длина пачки, стандартное количество хлыстов, расчет резов).
  - Учет обрезков для проекта и отдельный автономный калькулятор шинки.

### `js/nesting.js`
- **Ответственность**: 2D раскрой стандартных листов металла (2500 × 1250 мм) для прямоугольных воздуховодов с отрисовкой на HTML5 Canvas и экспортом карты раскроя в PDF.

### `js/finance.js`
- **Ответственность**: Учет оплат по объектам (внесение платежей, удаление), сводные финансовые ведомости для руководства, печать отчетов.

### `js/dev.js`
- **Ответственность**:
  - Панель разработчика: управление металлами, толщинами, бригадами, учетными записями работников.
  - **Конструктор изделий**: создание новых видов фасонины и редактирование существующих.
  - **Кастомные параметры изделий**: создание параметров с русским названием для интерфейса цеха и английским кодом для сохранения в JSONB базы Supabase.
  - Экспорт и архивация данных по месяцам в `.json`.

### `js/workers.js`
- **Ответственность**:
  - Расчет стоимости позиции и начислений мастеров (`getItemPositionCost()`).
  - **Умное распределение долей**: если участвует Разработчик Чингис (`isChingisOrDev`), он по умолчанию получает 50%, а остальные делят 50% поровну. Если Чингиса нет — делят 100% поровну.
  - **Личный кабинет мастера**: гармошка по объектам, детальный список позиций.
  - Статусы обновляются **точечно в DOM без перерисовки аккордеона**, чтобы список не сворачивался.

### `js/main.js`
- **Ответственность**: Слушатель `DOMContentLoaded`, вызов `loadInitialData()`.

## 4. Схема данных в Supabase

### Таблица `projects`
- `id` (bigint, PK)
- `title` (text) — Название объекта
- `description` (text) — Описание / заметки
- `group_name` (text) — Монтажная бригада
- `status_text` (text) — Текущий производственный статус
- `archive_state` (text) — `'active'` или `'archived'`
- `flange_settings` (jsonb) — Настройки фальцев и шинки:
  ```json
  {
    "pack_qty": 10,
    "lock_pittsburgh": 32,
    "lock_single": 9,
    "round_seam": 22,
    "scraps": []
  }
  ```

### Таблица `items`
- `id` (bigint, PK)
- `project_id` (bigint, FK -> projects.id)
- `item_key` (text) — Уникальный ключ конфигурации для автосуммирования количества
- `category` (text) — `'duct'` или `'fitting'`
- `shape` (text) — `'rect'`, `'round'`, `'smooth'`
- `title` (text) — Название изделия
- `metal` (text) — Вид металла (напр: `'Оцинкованная сталь'`)
- `thickness` (numeric) — Толщина в мм (по умолчанию 0.5)
- `qty` (integer) — Количество штук
- `price` (numeric) — Тариф за изготовление
- `workers` (text[]) — Массив имен назначенных мастеров
- `dimensions` (jsonb) — Все технические параметры и статус:
  ```json
  {
    "w": 400, "h": 300, "l": 1250,
    "flange1": true, "flange2": true,
    "item_status": "queue",
    "worker_shares": { "Чингис": 50, "Алексей": 50 }
  }
  ```

### Таблица `users`
- `id` (bigint, PK)
- `name` (text) — Имя мастера
- `access_code` (text) — Код доступа (PIN)
- `role` (text) — `'developer'` или `'worker'`

### Таблица `app_settings`
- `id` (text, PK = `'global_config'`)
- `metals` (text[])
- `thicknesses` (numeric[])
- `groups` (text[])
- `fittings` (jsonb) — Каталог фасонины с кастомными параметрами:
  ```json
  {
    "rect": [...],
    "round": [...],
    "smooth": [...],
    "__custom_params": [{ "code": "flange_offset", "label": "Вылет фланца" }]
  }
  ```

## 5. Правила для разработчиков и AI

1. **Не создавайте монолитных функций**: Если добавляете функционал, добавляйте его строго в профильный файл в папке `js/`.
2. **Точечные DOM-обновления**: Избегайте полной перерисовки списков (`innerHTML = ...`) при изменении отдельных свойств (например, статуса изделия), если открыт аккордеон. Используйте селекторы по ID элементов.
3. **Сохранение кастомных параметров**: Все новые параметры фасонины складываются в `dimensions` изделия в формате JSONB — дополнительных миграций БД не требуется.
4. **Контроль скобок и синтаксиса**: Перед коммитом всегда проверяйте синтаксис скриптов.
5. **Деплой**: Коммит и пуш в ветку `main` автоматически обновляет приложение на GitHub Pages.
